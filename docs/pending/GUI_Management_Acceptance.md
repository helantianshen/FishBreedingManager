# GUI 管理人工验收

状态：待执行。适用 Minecraft 1.21.1、NeoForge 21.1.244、Java 21。

本手册只记录测试步骤，不把编译或单元测试通过视为客户端通过。使用独立测试存档；涉及取消导入和删除规则的步骤不要在真实业务存档中执行。

## 启动与角色

运行 `./gradlew --no-daemon runClient`，创建或使用独立测试存档。输入 `/fbm gui` 或在世界中按默认快捷键 K 打开界面。可在原版按键设置的 Fish Breeding Manager 分类修改或取消“打开繁殖管理”的绑定。验证改键后新按键生效、旧按键不再打开界面，取消绑定后仍可通过命令打开。

准备单机未开启作弊和允许命令两种场景，并在多人测试服务器准备普通玩家、等级 1 OP、等级 2 OP。不同等级可由测试服控制台设置。GUI 入口与查询命令应全部可用；修改严格依据服务端有效权限，不依据游戏模式。

## 导航和桌面布局

1. 根菜单 `<` 置灰，点击不会关闭。点击“添加生物”后 `<` 回根菜单。
2. 从根菜单和添加页分别打开规则页；点击 `<` 应返回各自真实来源，而不是固定回根。
3. 从规则页打开物品或标签选择器，取消选择返回规则草稿；搜索、筛选、滚动位置保留。
4. 从上述每个页面和确认页点击 `X`，一次回到游戏。未保存草稿丢弃，不自动应用。Esc 应同样关闭；展开来源列表时第一次 Esc 仅收起选项。
5. 在 1920×1080、2560×1440、1280×720 和可用 GUI Scale 下测试。字体应为游戏当前字体；小逻辑尺寸下滚动编辑表单后，启用、食物、时间控件与底部操作均应可达。
6. 测试中文输入法、英文 ID、全选粘贴、Tab 与 Enter、滚轮、拖动滚动条；输入搜索时不得误提交规则。

## 公开查询与权限

1. 普通玩家和 OP 1 搜索鳕鱼、来源、非鱼实体，查看预览、所有食物与标签、冷却和成长值。写控件置灰并说明原因。
2. `/fbm rule list`、`/fbm rule show minecraft:cod` 可用；`reload`、`set`、`enable`、`disable`、`remove` 对普通玩家不可用。
3. OP 2 编辑中由控制台撤销权限，然后点击保存。必须拒绝写入并转为只读，原服务端规则不变。
4. 再授予权限并重新读取，确认写操作可用。创造模式但无 OP 的玩家仍只读。

## 编辑和精确时间

1. 选择鳕鱼，查看默认海带、30 秒冷却、60 秒成长。添加海草、替换物品、添加非空物品标签、删除一项，确认每个操作只改草稿。
2. 恢复默认只修改草稿；关闭后重新打开仍应为原规则。保存成功后才改变世界规则。
3. 输入 0、0.05 秒并保存；秒与分钟反复切换，保持精确 tick。0.01 秒、负数、空值、极大值必须显示错误并禁止保存。
4. 删除全部食物后，即使关闭启用开关，保存仍不可用。选择器取消替换不得删除原项，重复添加不得产生重复项。
5. 修改后 `<` 提供保存返回、放弃返回、继续编辑。`X` 始终直接关闭并放弃尚未提交的草稿。
6. 取消导入相关确认、待验证实体启用确认、保存失败、正在读取等状态都必须能退出。

## 导入与移除

1. 在完整 Registry 搜索一个尚未收录实体。仅添加到列表后，确认其状态为未配置，不能自动启用繁殖。
2. 添加成功后按钮变成编辑入口；填写规则并保存。无内建默认值时恢复默认应置灰。
3. 手动导入条目没有规则时取消导入。存在规则时，明确确认后一起删除导入标记和规则，取消确认则两者均不变。
4. 若该实体仍由自动发现收录，取消手动导入后仍应出现，并收到对应提示。
5. 正常保存退出、重进同一存档、跨维度检查数据；另一个存档不能继承这些修改。

## 并发、异常与预览

1. 两位 OP 同时编辑同一版本，先保存者成功，后保存者被告知重新读取；旧草稿不能覆盖新数据。通过命令修改也应使 GUI 基线失效。
2. 目录加载期间关闭后重开、保存中关闭、断开并重连。迟到回执不得重开页面或污染新连接；超时不能误报成功。
3. 预览仅显示客户端模型，不在世界产生实体；第三方模型失败时显示降级提示，查询仍可用。
4. 删除模组后的独立测试存档中，缺失实体应可诊断；规则未成功加载时说明仅展示未应用的存档信息，不能声称规则正在生效。
5. 已开始的实体冷却和幼体成长时间不因修改规则追溯变化。此项需要真实实体观察，不能只看 GUI 显示值。

- 检查鳕鱼、鲑鱼、热带鱼和河豚的卡片及详情预览：显示略微俯视的斜侧面，不显示离水侧躺后的背部；切换选中项和页面后保持一致。
- 在陆地和水中分别打开 GUI，预览朝向应一致；检查第三方实体预览以及关闭 GUI 后的世界渲染。

## 分类与卡片选中回归

- 在 IDEA 中启动客户端，按 K 打开管理页：“全部”应持续显示选中边框。
- 依次单击不同鱼卡片：仅当前鱼显示选中边框，整行不出现额外边框，“全部”的选中状态保持。
- 切换“原版”或“模组”，再选择卡片、输入搜索、进入子页后返回：分类标记始终对应当前筛选，实体最多选中一个。
- 用 Tab 和方向键进入列表，确认列表仍能获得焦点并通过 Enter 操作；添加生物、物品选择及来源下拉框的列表选中显示保持正常。
- 本节为待测步骤，尚未在客户端确认。

## 实体预览构图回归

- 在 IDEA 中启动客户端，检查四种鱼的卡片、详情及编辑页预览：模型居中，头尾与鱼鳍完整，四周有留白，热带鱼不贴底边，鲑鱼不截尾。
- 河豚显示完全膨胀形态，热带鱼显示橙白 KOB 变种；退出界面后世界中的实体形态与颜色不变。
- 在不同 GUI Scale 和窗口尺寸下复查构图；资源包替换模型及第三方模型仍需独立验证，原版模型校准不保证覆盖替换后的轮廓。
- 本节为待测步骤，不代表视觉验收已通过。

## 滚动条、来源与筛选回归

- 在 IDEA 客户端打开添加生物页，按住列表右侧滚动条滑块上下拖动，列表应跟随；拖出边界及松开后再移动鼠标，确认滚动停止，滚轮仍可用。详情、物品选择与来源长列表同样检查。
- 打开来源菜单，文字和背景应完整覆盖底层实体；点击菜单选项仅改变来源，不选中底层生物。点击外部或按 Esc 收起；来源较多时可拖动菜单滚动条。
- 连续开关“仅显示未添加”，勾选文字与结果同步；勾选时排除已添加实体，取消后恢复，并保持当前搜索与来源条件。
- 以上为待测步骤，尚未完成客户端交互验收。

## 来源菜单与列表样式

- 来源菜单应为深色不透明底、浅色边框和文字，带阴影；高度随选项数量收缩，较多选项仍可滚动。
- 当前来源带绿色箭头标记，鼠标悬停与键盘焦点有高亮；选择其他来源后标记同步变化。
- 添加生物列表显示交替行底色、悬停高亮及选中底色与边框，菜单和列表的视觉层级清晰。
- 上述样式仍待 IDEA 客户端实际观察。

## 空结果提示回归

- 主界面和添加生物页输入无匹配内容，空结果提示应居中显示在列表内部，不与表头重叠、不被背景遮住；清空搜索后提示消失，结果恢复。
- 空结果时打开来源菜单，菜单仍覆盖提示；调整窗口尺寸后提示仍位于列表内部。本项待客户端实测。

## 兼容性状态文案

- 主界面及添加生物页选中任意实体，详情不显示兼容性状态文字；已添加、已启用及未添加实体均不显示。此项待客户端确认。

## 原有繁殖食物读取

- IDEA 客户端进入添加生物页，普通玩家选中牛、猪等动物，稍等后在右侧查看“原有繁殖食物（读取）”；结果应匹配当前数据包下的食物。内容过长可滚动，说明文字被截断时悬停查看。
- 查询具有既有 FBM 配置的动物，应分开显示 FBM 规则与原有食物；查询不改变规则、启用状态、导入集合或世界实体，不要求 OP。
- 原版鱼等没有 Animal 食物接口的实体显示“未提供通用食物接口”；空匹配仅显示“未检测到匹配食物”，不据此声称完全不能繁殖。
- 选中使用通用接口的模组动物，验证普通物品匹配；特殊组件、状态条件和私有繁殖系统不在通用读取保证范围，无专用适配。
- 快速切换实体、关闭重开、切换世界及数据包重载，确认迟到回复不覆盖当前选择，重新读取可更新结果；查询失败仍可使用页面其他操作。
- 检测分批每会话每 tick 至多检查 64 个物品，最多返回 128 个匹配；超限和回调异常显示部分结果，网络超限显示错误。
- 自动化覆盖分批预算、仅调用食物判断、非 Animal、空结果、异常隔离、128 项上限和结果序列化；真实数据包与第三方模组行为仍待上述客户端验证。
