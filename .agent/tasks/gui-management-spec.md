# FBM GUI 管理功能 Spec

状态：功能实现与自动化检查完成，待客户端及联机人工验收。更新时间：2026-10-01。

本文件是当前 GUI 任务的有效规格与交接入口。以用户最后确认的 PC 端三张原型为视觉参考，以本文定义的行为为准；生成图片中的模拟数据、字形误差和遗漏控件不作为实现依据。完成开发后将长期约束整合进现行项目文档，删除本任务文件，不保留历史归档。

## 1. 目标与需求优先级

为 Minecraft 1.21.1 / NeoForge 21.1.244 / Java 21 提供可实际操作的繁殖管理 GUI，覆盖浏览、搜索、完整规则查询、规则编辑、实体导入与取消导入。

用户明确要求：

1. 所有页面的 `<` 仅返回上一级；最开始的主菜单没有上一级，按钮可见但置灰，点击不产生行为。
2. 所有页面的 `X` 直接关闭整个 FBM GUI，回到游戏，不逐层返回。
3. 每一个显示为可用的按钮必须有完整实际功能、成功反馈及失败处理，不允许占位按钮。
4. 查询、浏览、搜索等只读能力向任何玩家开放。
5. 修改、新增及其他改变世界规则或导入集合的操作必须由服务端校验 OP 权限。
6. 使用 PC 端紧凑布局和 Minecraft 原版字体渲染，避免移动端式大字号、大按钮。

当前 `.agent/PROJECT.md` 中“单机可编辑”的旧产品目标与第 5 项存在冲突。本 Spec 按最新要求执行：单机、局域网及独立服务器均使用服务端实际权限，不添加“单机直接放行”分支。原版服务端如何赋予单机玩家权限，遵循实际运行结果。Spec 获准实现后同步更新项目事实文档。

## 2. 已核实的实现基础

| 内容 | 当前事实与实现入口 |
| --- | --- |
| GUI | 尚无管理 Screen、物品选择器或 GUI 入口；客户端入口为 `FishBreedingManagerClient` |
| 权限 | `command/FBMCommands` 当前在 `/fbm` 根节点要求权限等级 2，查询也受限 |
| 规则 | `breeding/BreedingRule` 包含实体 ID、物品 ID 列表、物品标签列表、冷却 tick、成长 tick、启用状态 |
| 校验 | `breeding/RuleValidator` 校验注册项、非空食物来源、标签与非负计时；不等于实体兼容性认证 |
| 事务 | `breeding/WorldBreedingService` 复制完整规则集、校验后更新 SavedData 与运行时 Snapshot；失败保留旧状态 |
| 持久化 | `persistence/WorldBreedingData` 已保存规则及手动导入集合；导入管理尚无完整服务事务 |
| 发现 | `discovery/FishDiscoveryEngine` 的快照保留完整 Registry，包含置信度、来源与导入理由 |
| 兼容性 | 当前发现流程统一填充 `UNVERIFIED`；不能把原型中的“不支持”或“已验证”当作现成判定结果 |
| 网络 | `network/ModNetworking` 当前仅注册服务端到客户端的幼体状态同步 |
| 默认值 | 四种原版鱼默认启用，冷却 600 tick、成长 1200 tick；鳕鱼和河豚使用海带，鲑鱼使用海带及海草，热带鱼使用海草 |

当前根目录工作区在调查时无未提交改动；本阶段只形成规格，不实现 GUI。

## 3. 页面结构与入口

页面层级：

```text
繁殖管理（根页面）
├─ 规则详情 / 编辑繁殖规则
│  ├─ 选择物品
│  └─ 选择物品标签
└─ 添加生物（普通玩家也可进入搜索）
   └─ 规则详情 / 编辑繁殖规则
      ├─ 选择物品
      └─ 选择物品标签
```

提供 `/fbm gui` 入口，已进入世界的任何玩家均可使用。另注册“打开繁殖管理”快捷键，默认使用 K，玩家可在原版按键设置中修改或取消绑定。控制台执行 GUI 命令给出“仅玩家可打开界面”。无世界或服务端未提供管理协议时不打开可操作页面，说明原因。

调整命令根节点权限时，必须将既有写命令的权限要求下沉到写分支，防止根节点放开后写命令一并开放。`rule list`、`rule show` 同步开放给普通玩家；`reload`、`set`、`enable`、`disable`、`remove` 仍要求写权限。

## 4. 全局导航、退出与草稿

| 控件 / 操作 | 明确行为 |
| --- | --- |
| 根页面 `<` | 可见、置灰、不响应；提示“当前已是主菜单” |
| 子页面 `<` | 仅回到实际进入它的父页面，保留父页面搜索、筛选、选中项与滚动位置 |
| 任意页面右上 `X` | 一次关闭全部 FBM 页面及弹窗，清理本次会话草稿，回到游戏 |
| Esc | 下拉框展开时先收起下拉框；否则等同 `X`，关闭全部 GUI |
| 物品选择页 `<` | 取消尚未确认的选择，返回编辑页；已存在的规则草稿不丢失 |
| 弹窗“取消 / 继续编辑” | 仅撤销当前动作并回到发起位置 |
| 鼠标点击窗口外 | 不关闭、不保存 |

`X` 按用户要求直接关闭，不弹“是否保存”确认，也不自动保存。编辑页出现未保存变更时，常驻显示“有未保存修改；关闭将放弃”。该行为同样适用于选择器和确认弹窗内的 `X`。

编辑页 `<` 遇到未保存修改时显示“保存并返回 / 放弃修改并返回 / 继续编辑”。保存失败留在编辑页并保留草稿；字段无效或权限不足时，“保存并返回”禁用，其余两个选择有效。无变更时直接返回。

关闭 GUI 不撤销已经提交到服务端的请求。请求在途时可关闭；服务端已成功提交则规则仍生效，回执仅给简短游戏内反馈，不重新打开界面。重新打开时重新读取权威数据。未发送的草稿不得因关闭而提交。

断开连接或切换世界清理页面、草稿、预览对象及数据缓存。所有页面不暂停世界，单机与多人行为一致。

## 5. 权限合同

拟采用项目已有权限等级：服务端玩家 `hasPermissions(2)`，即等级 2 及以上允许写入，等级 0、1 只读。这里的“OP”按原版权限等级定义，不以客户端创造模式、玩家名称或客户端布尔值判断。用户尚未指定等级，等级 2 是本 Spec 的明确建议，审查时可调整。

| 能力 | 普通玩家 / OP 1 | OP 2–4 |
| --- | --- | --- |
| 打开 / 返回 / 关闭 GUI | 允许 | 允许 |
| 查询列表、搜索、来源筛选、状态筛选 | 允许 | 允许 |
| 查看实体预览、全部规则、物品和标签 | 允许 | 允许 |
| 进入添加生物页浏览完整 Registry | 允许 | 允许 |
| 修改启用、食物、冷却、成长 | 禁止 | 允许 |
| 保存新增或修改规则 | 禁止 | 允许 |
| 恢复默认并保存 | 禁止 | 允许 |
| 添加到管理列表 | 禁止 | 允许 |
| 取消手动导入、删除关联规则 | 禁止 | 允许 |
| 执行管理重载 | 禁止 | 允许 |

普通玩家进入详情页时标题为“繁殖规则”，显示“只读：修改需要 OP 权限”。文本与完整物品列表正常可读；修改控件和保存按钮置灰并说明原因，不能把整页挡住。主页面入口对应显示“查看繁殖规则”。无规则时显示“尚未配置规则”，普通玩家仍可查看实体资料。

服务端读取请求不要求写权限。每次写请求在服务端执行时重新校验当前发起玩家、当前连接、当前世界、OP 等级、目标实体与参数。客户端隐藏或置灰仅改善体验，不能作为安全保障。

打开界面后被撤销权限的玩家，后续写入必须被拒绝且数据零变化。拒绝响应同时刷新只读状态，保留草稿供查看但禁止保存。授予权限后通过重新获取页面数据更新控件；不每 tick 查询权限。

## 6. 页面 A：繁殖管理

### 6.1 列表范围与状态

列表为自动发现的中 / 高置信度候选、手动导入实体、已有规则实体的并集，按 Registry ID 去重。判定自动候选时不把单独的 `IMPORTED` 理由计作自动收录依据，避免取消导入后候选因导入置信度继续残留。高级搜索仍查询完整 Registry。

主列表不是已启用规则清单：自动发现可以没有规则，导入也不自动启用。条目分别显示“已启用 / 已停用 / 未配置”，不要把这三种状态都显示成“未启用”。已有数据中的缺失 Registry ID 保留可见诊断条目，禁止编辑并显示“实体已不可用”，不静默删除存档数据。

### 6.2 控件行为

| 控件 | 行为及边界 |
| --- | --- |
| 全部 / 原版 / 模组 | 在当前列表范围内切换来源；原版按 `minecraft` namespace，模组为其余来源 |
| 搜索框 | 按当前语言显示名和完整 Registry ID 忽略拉丁字母大小写匹配，去除首尾空白；与分类取交集，清空恢复全部 |
| 生物卡片 | 单击选中并刷新右侧；双击打开相同规则页，普通玩家进入只读模式 |
| 列表滚动条 / 滚轮 | 只滚动指针所在列表；不能修改右侧选择或误触按钮 |
| 编辑 / 查看繁殖规则 | 打开当前实体完整规则；无选择时禁用 |
| 添加生物 | 任何玩家可进入页面 B 搜索；写权限只影响页面内实际添加操作 |
| `<` / `X` | 遵守第 4 节 |

右侧展示名称、Registry ID、来源、预览、规则状态、完整食物来源、冷却与成长时间。超过显示范围的食物用可滚动区域呈现，不截断为不可访问的信息。长名称省略并提供完整悬停提示。

默认稳定按来源 ID、实体 ID 排序。搜索改变后滚动到顶部；原选中项仍在结果内则保留，否则清空详情并提示选择。空结果显示“没有匹配的生物”，保留搜索、分类与添加入口。

## 7. 页面 B：添加生物 / 完整 Registry 搜索

所有玩家都能查询完整 EntityType Registry；不能仅返回鱼类候选。来源下拉框根据真实已加载来源构建，无模组时仍正常工作。保留列表滚动，首版不使用可见分页按钮。

| 控件 | 行为及边界 |
| --- | --- |
| 搜索框 | 与主界面相同的名称 / ID 搜索规则 |
| 来源下拉框 | 全部或指定来源，选项来自服务端权威目录；支持键盘和滚轮 |
| 仅显示未添加 | 默认不勾选；勾选后排除主列表已包含的实体，与其他条件取交集 |
| 实体行 | 单击查看；双击仅对已收录实体打开规则页，不直接导入 |
| 添加到管理列表 | 仅有写权限、实体存在、未收录且非已知不支持时可用；服务端成功后显示“已添加”，刷新父列表 |
| 编辑 / 查看繁殖规则 | 已收录实体显示此主操作；添加成功后原按钮原位变为此操作 |
| 取消手动导入 | 仅对手动导入条目显示，普通玩家置灰；行为见下文 |
| `<` / `X` | 遵守第 4 节 |

“管理状态”显示已添加、未添加或不可用；详情说明自动发现、手动导入、已有规则等来源。“繁殖状态”独立显示已启用、已停用或未配置。兼容性状态文字按用户最新要求暂不显示，不用“不支持”替代管理状态。

添加只修改当前世界的导入集合，不新建规则、不启用繁殖、不生成实体。无规则实体首次编辑草稿默认关闭繁殖、食物为空、冷却 30 秒、成长 60 秒；这些是输入初值，不是其经过验证的默认繁殖方案。

取消手动导入的建议合同：

1. 没有关联规则：移除手动导入标记；若实体仍符合自动发现条件，它仍留在主列表，并明确提示“已取消手动导入，仍由自动发现收录”。
2. 有关联规则：必须弹出确认，列出实体名称、ID，说明将取消手动导入并删除该实体繁殖规则，后续不再通过该规则触发繁殖；既有实体不删除，已开始的冷却 / 成长不重算。按钮为“取消导入并删除规则 / 取消”。
3. 导入标记和关联规则删除必须作为一个服务端事务成功或失败，不能只完成一半。
4. 自动发现条目无手动导入标记时不显示该按钮，不能承诺永久隐藏自动发现条目；停止繁殖使用规则启用开关。
5. 该删除语义属于本 Spec 待审查的产品取舍；其他可选行为是取消标记并保留规则，但条目会因已有规则继续出现在主列表，且繁殖仍可能启用。实现前以用户对本 Spec 的审查结论为准。

## 8. 页面 C：规则详情 / 编辑

编辑只操作客户端草稿，直到明确保存。所有字段来自服务端最新规则，不能用原型默认数值覆盖现有配置。

| 控件 | 行为及禁用条件 |
| --- | --- |
| 启用繁殖 | 切换草稿 enabled，不即时提交；普通玩家禁用 |
| 物品行 / 铅笔 | 打开物品选择器替换当前项，取消不改变原项 |
| 物品标签行 / 铅笔 | 打开标签选择器替换当前标签，显示完整 `#namespace:path` |
| 行内删除图标 | 删除草稿中的该项；允许暂时为空，但保存时必须满足非空食物来源 |
| 添加物品 | 打开当前 Item Registry 的搜索选择器，确认后加入草稿，重复项不重复插入 |
| 添加物品标签 | 打开当前非空物品标签选择器，支持 ID 搜索与成员预览；不能仅放置无功能按钮 |
| 冷却 / 成长输入 | 支持数字输入、选择、复制粘贴，验证后显示逐字段错误 |
| 秒 / 分钟单位 | 仅改变展示单位，保持实际 tick 时长；不通过切换单位四舍五入覆盖原值 |
| 恢复默认 | 仅对存在内建默认规则的实体可用，将默认值写入草稿，仍需保存才生效；其他实体置灰并提示“此实体没有默认规则” |
| 保存并应用 | 有写权限、数据完整有效、有实际变更且无在途保存时可用；成功后返回实际父页并刷新选择与详情 |
| `<` / `X` | 遵守第 4 节 |

### 8.1 时间和食物校验

- 与当前规则模型一致，冷却和成长允许 0，不能为负；单位为游戏 tick，20 tick 表示 1 游戏秒，并非服务器低 TPS 时的保证墙钟时间。
- 最终 tick 必须是 `0..2147483647` 的整数。采用十进制定点计算；不能溢出、静默截断或转换为负数。
- 允许小数输入，但换算必须恰好是整数 tick；例如 0.05 秒合法，0.01 秒非法。单位切换保留规范 tick 值；分钟展示若无法有限精确表示，使用只读近似提示而不修改底层值，用户主动重新输入才重新验证。
- 现有命令写入的非整秒 tick 值必须可无损读取及保存，不能因打开页面就变更。
- 至少一个有效物品或物品标签；关闭繁殖仍遵循当前校验器的食物非空要求。
- 服务端复用并补足 `RuleValidator` 的真实非空标签校验，未知实体、未知物品、未知或空标签、重复来源规范化、超限字段都不能进入持久化。
- 单次规则最多 128 个物品与标签来源合计；这是 GUI 协议资源上限的建议值，不删改旧数据。超过上限的已有规则仍完整可读，编辑页明确提示需要减少条目后才能保存。

### 8.2 物品与标签选择器

选择器属于可返回的子页面，仍带全局 `<` 与 `X`。包含搜索框、滚动结果、选中信息、“确认选择”按钮。无选择时确认禁用；标签显示 ID、成员数量和可滚动的物品预览。替换时原选项预选，加入后回到编辑页并保留其滚动位置。读取目录允许所有玩家，只有可编辑会话允许确认修改草稿。

## 9. 兼容性与实体预览

自动发现置信度只说明识别线索，不代表繁殖、导航或渲染已通过验证。

- FULL / PARTIAL 只能来自有事实依据的兼容性信息；PARTIAL 显示具体限制。
- UNVERIFIED 可查询、可由 OP 导入；首次启用保存时明确提示“尚未验证该实体的繁殖兼容性”，需要在该次保存流程确认。不得把导入成功改写为兼容验证通过。
- 已有可靠判定的 UNSUPPORTED 允许查询，禁止新增和编辑提交，并给出具体原因；客户端伪造确认也不能绕过服务端拒绝。
- 不通过命名、外观或模型推断“不支持”。当前系统缺少完整判定，必须如实保留“待验证”，首版不承诺完整兼容检测器。

预览使用真实游戏实体模型和当前资源，采用固定观察角度。首版不放旋转按钮，不实现自动旋转。只对当前可见卡片和选中实体创建必要的客户端预览对象，不扫描并实例化整个 Registry、不加入真实世界、不运行 AI、不触发服务端生成。失败时回退占位图与“预览不可用”，保留浏览和权限允许的操作。退出界面释放缓存。

## 10. PC 布局、字体与输入

- 使用 Minecraft 当前 Font、原版控件与纹理资源；不把生成图中文字烘焙成纹理，不额外捆绑仿 MC 字体。默认资源下必须与原版字体一致，尊重玩家语言、强制 Unicode 字体及资源包。
- 尺寸用 Minecraft GUI 缩放后的逻辑坐标，不能直接照抄原型物理像素。按钮优先沿用约 20 逻辑像素的原版高度，正文原版字号。
- 桌面三栏主界面、紧凑编辑表单、密集注册表列表；窗口四周保留背景，随可用逻辑尺寸约束窗口，不强行占满屏幕。
- 窄逻辑窗口优先缩小预览、减少网格列数、使内容区滚动；导航与底部主要操作必须可见可达，不擅自改动用户 GUI Scale。
- 搜索框支持输入法、中文、全选、粘贴；Tab / Shift+Tab 遍历可操作控件，Enter 只激活焦点按钮，不在搜索输入时误提交规则。
- 已聚焦文本框优先接收键盘输入，打开 GUI 的快捷键不能在输入时再次触发。
- 禁用态视觉清楚且有原因提示；不能只靠红绿颜色传达状态。长文本提供悬停或换行，避免盖住按钮。

## 11. 服务端协议和事务边界

本节定义职责和数据合同，不强制为每个动作创建独立类。具体 Payload 命名可在实现中按现有风格确定。

### 11.1 读取

打开会话获取：当前世界管理修订号、当前玩家 canEdit、实体目录及来源、收录信息、兼容性信息、规则摘要。按需查询实体完整规则及物品 / 标签目录。

实体目录以服务端 Registry 为准；名称以翻译键在客户端当前语言解析，缺失时回退 ID。完整目录可分块传输并在客户端做名称 / ID 搜索，前端滚动不要求每次键入都触发服务端扫描。分块必须能检测缺块、超限和过期结果，不能把未收齐误判为完整空结果。

只读查询禁止调用会种入默认规则、修改 importedEntities、标记 SavedData dirty 或重载世界规则的写路径。使用已经由服务器生命周期初始化的管理器数据。

### 11.2 写入

每个请求带请求 ID、目标实体 ID、读取时的世界管理修订号和必要意图参数。动作至少覆盖保存完整规则、手动导入、取消导入并按确认意图删除关联规则。恢复默认在客户端填充草稿，最终仍通过保存事务。

处理顺序：验证发起玩家与权限 → 解码及资源上限 → 目标存在性和操作适用性 → 修订号 / 当前状态 → 参数及兼容性校验 → 构造候选 → 完整校验 → 原子发布持久化工作集、规则快照、导入 / 发现视图 → 增加修订号 → 返回权威结果。

所有修改在服务端合法线程执行，GUI 不直接操作 SavedData。扩展现有 `WorldBreedingService` 或其紧邻服务以支持导入集合与规则一起提交，不另建平行规则存储。发现视图必须先构建成功再发布，失败不能留下半更新的导入状态。兼容实体刷新保留既有 best-effort 边界，已提交后的兼容刷新失败不得谎报事务已回滚。

命令与 GUI 的管理变更必须共同推进管理修订号。首版可采用当前世界单一递增修订号；管理员修改其他实体也可能触发保守冲突，这是明确取舍。冲突时不覆盖新数据，保留草稿，提示重新加载后检查并重试，不自动重放写入。

成功响应返回新修订号及目标权威状态；正在浏览的其他客户端收到轻量失效通知，读取页刷新，编辑页保留草稿并标记数据已变更。没有 GUI 会话的玩家不持续接收完整目录。

重复点击发送前禁用写按钮；服务端同一连接重复请求 ID 返回原结果，不重复提交。写请求超时属于结果未知，先查询权威状态，不盲目重发或显示保存成功。关闭后迟到响应不复活页面。

### 11.3 错误合同

至少覆盖：无权限、实体不存在、不支持、规则无效、标签为空、数据冲突、已导入、非手动导入、请求超限、服务端失败、协议不可用、超时结果未知。错误显示可理解文案，保留相关输入，不把内部堆栈发给玩家。

设置有界字符串、集合和数据块尺寸；目录按实际编码大小分块，单块建议不超过 24 KiB，须在实现时以当前 NeoForge 依赖的实际 Payload 上限验证。每个连接最多一个进行中的目录装载，同类请求合并或限频；权限不通过的写请求在昂贵工作前拒绝。

SavedData 提交表示更新服务器内存权威状态并标记待保存；磁盘落盘遵循 Minecraft 保存生命周期，不承诺“按钮成功即同步 fsync”。正常保存退出并重进必须保持数据。

## 12. 按钮完整性与反馈原则

所有按钮必须落入以下一种状态：可执行并有结果；因具体条件禁用并有原因；仅在条件成立时显示。不能保留“以后实现”的可点击按钮。图标按钮、下拉箭头、滚动条、确认弹窗和键盘触发同样纳入验收。

加载期间显示正在读取，禁止依赖缺失数据的写操作；失败提供实际有效的“重试”按钮。保存、导入、移除均显示进行中状态。成功反馈只在服务端确认后显示。空结果与网络失败必须使用不同文案。

`X` 始终可用于直接退出；根 `<` 按定义禁用；保存失败、预览失败、数据加载失败都不能把玩家困在页面中。
