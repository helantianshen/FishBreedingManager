# 代码注释规则
注释使用中文。标识符、API、类型名、命令、路径、协议名和报错原文保持原样，不翻译。
每条注释写完整，最后一行不得以中文逗号、顿号、分号、冒号或句号收尾；中文句子使用全角标点，代码片段与英文术语保持半角。
语言自然、简洁、精确，只写读代码得不到的信息。解释为什么与必要前提，不复述代码本身，不为每行、每个函数补注释，不写长篇说明。
注释可放在声明、函数签名、类型与字段、结构体标签，以及函数体内的关键语句上。显而易见的行为不加注释。
只描述当前真实存在的行为与约束：不变量、单位、边界与误差、所有权与生命周期、并发前提、错误语义、副作用、外部协议与兼容性要求。只有存在真实替代方案且必须说明时才写理由。
不描述变更与决策过程：不写“改为、不再、之前、原来、修复、新增、优化、之所以选择”，也不把没有真实替代方案的实现选择写成决策或取舍。
不描述尚未存在的计划：不写未实现的行为、未来优化与猜测。TODO 与 FIXME 只在项目规范允许时保留，并写明触发条件与范围。
不写被注释掉的废弃代码、调试输出、分隔线、装饰性横幅、表情、署名，也不用注释代替日志、提交信息、需求单号或评审记录。
注释与代码不一致时以代码为准修正注释，删除无信息的残留注释。
文档注释遵循语言与项目既有约定（GoDoc、JSDoc、docstring、rustdoc 等），注释符号、标签、缩进、行宽与段落间距与文件内既有风格一致。
项目或用户已有更具体的注释规范时以它为准。
